# 在系统托盘关于页面增加检查更新功能实施计划

## 目标

在系统托盘“关于”页面中增加“检查更新”能力，并让关于页面的视觉风格与当前应用深色主题、设置页和按钮体系保持一致。

## 现状分析

* 托盘菜单由 `SystemTrayService` 通过 Win32 菜单创建，“关于”内容不是独立窗口，而是由 `About_Click()` 动态拼装 WPF 内容后展示。

* 当前项目没有现成的“检查更新”服务，也没有版本源配置。

* 应用已有统一色板与按钮样式，位于 `Styles/ModernStyles.xaml`。

* 项目已引用 `HandyControl`，可用于补充统一风格的消息反馈，但不应大范围改造现有 UI 结构。

* 当前设置窗口采用左右分栏深色风格，因此关于页也应延续相同的深色卡片、主次文本、主次按钮层级。

## 实施步骤

### 1. 明确更新来源与数据模型

实现前先确认检查更新的远端来源，优先采用稳定且无需鉴权的版本清单接口，例如：

* GitHub Releases API

* 自有静态 JSON 文件

* 其他公开可访问版本接口

计划新增一个最小化版本信息模型，包含：

* 最新版本号

* 发布标题或版本名

* 发布时间

* 更新说明摘要

* 下载地址

为了避免将外部协议耦合到 UI，先用内部 DTO 承载远端数据，再转换为界面展示文本。

### 2. 新增检查更新服务

在 `Services` 下新增一个专用更新服务，职责尽量单一：

* 读取当前程序集版本

* 访问远端版本源

* 解析最新版本信息

* 与当前版本比较

* 返回统一结果对象（是否有新版本、提示文案、下载链接、失败原因）

设计要求：

* 使用异步 API，避免阻塞 UI 线程

* 仅做只读网络请求，不引入自动下载或自动安装

* 网络异常、解析异常都转为用户可理解的失败结果

* 不记录敏感信息，不写入本地配置

### 3. 扩展应用配置承载更新源

如果更新源需要可维护配置，则在现有配置体系中增加最小必要字段，例如：

* 更新接口地址

* 下载页地址

若来源固定且短期不会变化，也可先放在常量中，避免过度设计。最终实现时以“最少改动”为准。

### 4. 重构托盘关于页面 UI 结构

保留 `About_Click()` 作为入口，但将内容构造拆分为更清晰的方法，避免单个方法持续膨胀。

计划将关于页内容拆为几个视觉区块：

* 应用标题区：名称、当前版本、简短描述

* 信息区：产品名、运行框架或版权信息

* 更新区：检查更新按钮、状态文本、可选的下载入口

* 操作区：关闭/确定按钮

UI 统一原则：

* 使用与 `ModernStyles.xaml` 一致的背景、边框、文本和按钮资源

* 主按钮用于“检查更新”或“前往下载”

* 次按钮用于关闭

* 主标题、辅助说明、状态信息建立明确层级

* 保持间距、圆角、阴影风格与设置窗口一致

### 5. 为关于页加入交互状态

检查更新是异步行为，因此关于页至少需要三种状态：

* 未检查：提示可手动检查最新版本

* 检查中：按钮禁用，展示“正在检查”状态

* 已完成：显示“已是最新版本”或“发现新版本”

* 失败：显示失败原因，并允许重试

实现建议：

* 在按钮点击时立即更新状态文本

* 检查完成后更新文本与后续按钮行为

* 若有新版本，提供“打开下载页”动作

* 如使用 HandyControl，则用于结果提示或错误弹窗，不替代核心状态区

### 6. 版本比较策略

采用 `System.Version` 做基础比较，并兼容当前 `csproj` 中的版本格式：

* 当前项目版本为 `1.3.1`

* 若远端含前缀 `v1.3.2`，需先做规范化处理后再比较

* 若格式不合法，则返回可识别错误，不让界面崩溃

### 7. 控制改动范围，保持结构稳定

本次只做与需求直接相关的修改：

* `SystemTrayService`：增加关于页更新区与交互调用

* `Services`：增加更新检查服务

* 必要时补充模型/常量

* 视情况小幅补充 `ModernStyles.xaml` 中可复用样式，但避免牵动全局已有控件表现

不做以下扩展：

* 不增加自动更新安装

* 不增加后台静默检查

* 不增加设置页更新配置入口

* 不重构整个托盘菜单系统

### 8. 验证方案

实现后按以下顺序验证：

1. 编译项目，确保新增服务和 UI 代码无错误
2. 从托盘菜单打开“关于”，确认样式与现有深色主题一致
3. 点击“检查更新”，验证：

   * 检查中状态展示正常

   * 成功时能区分“已是最新版本”和“发现新版本”

   * 失败时有明确提示且不会卡死界面
4. 如提供下载链接，验证链接可正常打开默认浏览器
5. 运行测试项目或至少完成解决方案构建
6. 按工作区规则执行代码审查

## 预计涉及文件

* `ToDoapp/Services/SystemTrayService.cs`

* `ToDoapp/Services/` 下新增更新服务文件

* `ToDoapp/Models/` 下视需要新增版本结果模型

* `ToDoapp/Styles/ModernStyles.xaml`（仅在需要抽取复用样式时修改）

* `ToDoapp/ToDoapp.csproj`（仅当需要补充与网络或资源相关的配置时修改）

## 实施时的关键注意点

* 保持现有代码风格，不做无关重构

* 由于托盘服务当前直接操作 UI，新增逻辑时要注意 Dispatcher 与异步回调的线程安全

* 关于页是动态构建内容，需避免事件处理器泄漏和重复创建过多闭包逻辑

* 如果远端版本源尚未明确，实施前应先确定具体接口，否则更新服务只能先做占位
